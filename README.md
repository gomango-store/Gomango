# GOMANGO 파트너 게시판

카페 바이저가 점주들에게 신메뉴 제조법 영상, 공지사항, 건의함/FAQ, 자료실을 안내하는 내부 게시판입니다.
별도 서버 없이 정적 HTML + Supabase(DB/인증)만으로 동작하며, GitHub Pages로 배포합니다.

## 폴더 구조

```
juicy-board/
├─ home.html           홈 대시보드
├─ index.html          루트 주소(/) 접속 시 home.html로 자동 이동시키는 리다이렉트용 파일
├─ login.html          로그인
├─ recipes.html         레시피 (목록 + 상세)
├─ notices.html         공지사항
├─ suggestions.html     건의함
├─ faq.html             자주 묻는 질문 (FAQ)

├─ assets/
│  ├─ style.css         공용 디자인
│  ├─ supabaseClient.js Supabase 연결 설정 (URL/키를 여기에 입력)

│  └─ functions/

   ├─ schema.sql                     Supabase에 실행할 테이블/보안정책 스크립트 (신규 설치용, 전체)
```

## ⚠️ 이미 사용 중이라면 먼저 이 SQL부터 실행하세요

이미 Supabase 프로젝트를 만들어서 사용 중이라면, `sql/schema.sql` 전체를 다시 실행할 필요 없이
아래 파일들만 SQL Editor에 순서대로 붙여넣고 Run 하면 됩니다 (여러 번 실행해도 안전합니다).

1. **`sql/02_edit_delete_migration.sql`** — 게시글 수정/삭제 기능에 필요
2. **`sql/03_gomango_update.sql`** — 건의함 구분(문의사항/건의사항/메뉴 의견), 발주 물품 단가 설정, 송금 상태에 필요 (02번을 먼저 실행하지 않았어도 이 파일 하나만으로 동작합니다)
3. **`sql/04_order_items_bundle.sql`** — 발주 요청 하나에 물품을 여러 개 담아 목록에 한 건으로 묶어서 보이게 하려면 필요 (이전 파일들을 먼저 실행하지 않았어도 이 파일만으로 동작합니다)
4. **`sql/05_service_role_grant.sql`** — **계정관리(accounts.html) 화면이 정상 동작하려면 반드시 필요합니다.** 이 파일을 실행하지 않으면 계정관리 화면에서 "permission denied for table profiles" 오류가 발생합니다 (이전 파일들을 먼저 실행하지 않았어도 이 파일만으로 동작합니다)
5. **`sql/06_notices_image.sql`** — 공지사항에 이미지(구글 드라이브 링크)를 첨부하려면 필요합니다 (이전 파일들을 먼저 실행하지 않았어도 이 파일만으로 동작합니다)

처음 설치하는 경우에는 아래 1~2단계에서 `schema.sql` 전체를 한 번만 실행하면 되고, 별도로
마이그레이션 파일을 또 실행할 필요는 없습니다 (schema.sql 안에 이미 다 포함되어 있습니다).

## 1단계. Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com) 에서 새 프로젝트를 만듭니다. (Free 플랜으로 시작 가능)
2. 왼쪽 메뉴 **SQL Editor** 로 들어가서 `sql/schema.sql` 파일 내용을 전체 복사해서 붙여넣고 실행(Run)합니다.
   - `profiles`(점주/바이저 정보), `notices`(공지), `recipes`(레시피), `faqs`, `suggestions`(건의사항), `suggestion_replies`(답변), `resources`(자료실), `companies`(업체 정보), `supply_requests`/`supply_request_comments`(본사 발주) 테이블과 보안 정책(RLS)이 한 번에 생성됩니다.
3. 왼쪽 메뉴 **Project Settings > API** 로 들어가서 `Project URL` 과 `anon public` 키를 복사해둡니다.

## 2단계. 코드에 Supabase 정보 연결

`assets/supabaseClient.js` 파일을 열어 두 값을 방금 복사한 값으로 바꿔주세요.

```js
const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi....";
```

(anon key는 공개되어도 되는 키입니다. 실제 접근 권한은 Supabase의 RLS 정책이 통제합니다. `service_role` 키는 절대 이 파일에 넣지 마세요.)

## 3단계. GitHub로 배포 (도메인)

1. GitHub에서 새 저장소를 만들고(예: `juicy-board`), 이 폴더 안의 파일 전체를 업로드/푸시합니다.
2. 저장소의 **Settings > Pages** 로 들어가서 Source를 `main` 브랜치, 폴더는 `/ (root)` 로 설정 후 저장합니다.
3. 몇 분 뒤 `https://<계정이름>.github.io/juicy-board/` 형태의 주소가 생성됩니다. 이 주소를 점주들에게 공유하면 됩니다.
4. 회사 도메인을 따로 연결하고 싶다면 같은 Pages 설정 화면의 **Custom domain** 에 도메인을 입력하고, 도메인 등록업체(가비아 등)에서 CNAME 레코드를 GitHub Pages 주소로 설정하면 됩니다. (필수는 아니며, 없어도 github.io 주소로 바로 사용 가능합니다.)

## 4단계. 계정 생성 방법 (바이저 → 점주)

로그인/계정 생성은 Supabase Auth가 처리하며, 이번 구성은 **바이저가 점주 계정을 직접 만들어주는 방식**입니다 (점주가 스스로 가입하는 화면은 만들지 않았습니다).

이제는 Supabase 대시보드를 거치지 않고, 바이저 계정으로 로그인한 뒤 상단 메뉴의 **"계정관리"**(`accounts.html`, 바이저에게만 보입니다) 화면에서 계정 추가/수정/삭제를 바로 할 수 있습니다. 다만 계정 생성·삭제는 Supabase의 관리자 권한(service_role)이 필요한 작업이라, 이를 안전하게 대신 처리해줄 **Edge Function을 한 번 배포**해야 합니다 (아래 4-1단계). 배포는 한 번만 해두면 그 뒤로는 계속 화면에서 계정을 관리할 수 있습니다.

### 4-1단계. Edge Function 배포 (최초 1회)

계정 생성/수정/삭제 버튼을 누르면 브라우저가 `admin-users`라는 Edge Function을 호출합니다. 이 함수는 Supabase 서버 쪽에서 "호출한 사람이 실제로 바이저인지"를 확인한 뒤에만 계정을 만들거나 지우기 때문에, 이 함수를 먼저 배포해야 계정관리 화면이 정상 동작합니다. **CLI 설치는 필수가 아니며**, 아래 두 방법 중 편한 쪽으로 하시면 됩니다.

**방법 A. 대시보드에서 바로 배포 (설치 없이, 가장 간단)**

1. Supabase 대시보드 → 왼쪽 메뉴 **Edge Functions** → **Deploy a new function** → **Via Editor** 선택.
2. 함수 이름에 `admin-users` 입력.
3. `supabase/functions/admin-users/index.ts` 파일 내용을 전체 복사해서 에디터에 붙여넣기.
4. **Deploy function** 클릭 (10~30초 소요).
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase가 자동으로 넣어주므로 따로 설정할 게 없습니다.
   - 참고로 대시보드 편집기는 버전 관리/롤백 기능이 없어서, 나중에 이 함수 코드를 자주 수정할 계획이면 방법 B(CLI)가 더 편할 수 있습니다. 지금처럼 한 번 배포해두고 그대로 쓰실 거면 이 방법으로 충분합니다.

**방법 B. Supabase CLI로 배포**

1. 컴퓨터에 [Supabase CLI](https://supabase.com/docs/guides/cli/getting-started)를 설치합니다. (예: `npm install -g supabase` 또는 `brew install supabase/tap/supabase`)
2. 이 폴더(`juicy-board/`)에서 터미널을 열고 아래 명령을 순서대로 실행합니다.

   ```bash
   supabase login
   supabase link --project-ref <프로젝트 참조 ID>
   supabase functions deploy admin-users
   ```

   - `<프로젝트 참조 ID>`는 Supabase 대시보드 프로젝트 URL(`https://<프로젝트 참조 ID>.supabase.co`)의 그 부분입니다. **Project Settings > General**에서도 확인할 수 있습니다.

두 방법 모두 배포가 끝나면 **Edge Functions** 목록에 `admin-users`가 보이면 정상입니다.

### 4-2단계. 계정관리 화면 사용법

1. 바이저 계정으로 로그인합니다. (처음 바이저 계정이 하나도 없다면, 아래 "최초 바이저 계정 만들기"를 먼저 진행하세요.)
2. 상단 메뉴의 **"계정관리"**로 들어가서 "+ 계정 추가" 버튼을 누릅니다.
3. **아이디**(예: `store01`, 영문/숫자/`.`/`_`/`-`만 사용, 2~40자) / 권한(점주 · 바이저) / 매장명 / 비밀번호(6자 이상)를 입력하고 등록하면 바로 로그인 가능한 계정이 만들어집니다.
4. 목록에서 "수정" 버튼으로 매장명·권한을 바꾸거나 비밀번호를 재설정할 수 있고, "삭제" 버튼으로 계정을 제거할 수 있습니다. (본인 계정은 삭제할 수 없도록 막아뒀습니다.)

> **로그인은 이메일이 아니라 "아이디"로 합니다.** Supabase Auth 자체는 이메일 기반이라, 화면에 입력한 아이디를 내부적으로 `아이디@juicy-board.local`이라는 실재하지 않는 이메일 주소로 바꿔서 저장·로그인 처리합니다. 실제로 발송되는 이메일이 아니므로 "비밀번호 찾기" 메일 발송 기능은 사용할 수 없고, 비밀번호를 잊었을 때는 계정관리 화면에서 바이저가 직접 재설정해줘야 합니다(지금 구조에서도 원래 이 방법뿐이었습니다).

### 최초 바이저 계정 만들기 (계정관리 화면을 처음 열 사람이 아직 없을 때만)

계정관리 화면 자체를 바이저만 볼 수 있기 때문에, 맨 처음 바이저 계정 1개는 예외적으로 Supabase 대시보드에서 만들어야 합니다. 이후부터는 계정관리 화면에서 바이저 계정도 추가할 수 있습니다.

1. Supabase 대시보드 왼쪽 메뉴 **Authentication > Users** → **Add user** → **Create new user**.
2. 이메일 입력란에 `원하는아이디@juicy-board.local` 형식으로 입력합니다. (예: 로그인 화면에서 "본사"라는 아이디로 로그인하게 하고 싶다면 `본사` 대신 영문/숫자로 `hq@juicy-board.local`처럼 입력하세요 — 로그인 화면의 아이디 입력란은 영문/숫자/`.`/`_`/`-`만 지원합니다.) 비밀번호도 함께 입력하고 저장합니다.
3. 저장된 계정의 **UID(uuid)**를 복사한 뒤, 왼쪽 메뉴 **SQL Editor**에서 아래 SQL을 실행합니다.

   ```sql
   update public.profiles
   set store_name = '본사', role = 'visor'
   where id = '<복사한 UID>';
   ```
4. 이 계정으로 로그인할 때는 로그인 화면 "아이디"란에 `hq`(위에서 이메일 앞부분으로 정한 값)만 입력하면 됩니다. 로그인 후 "계정관리" 메뉴가 보이고, 이후 점주/추가 바이저 계정은 전부 그 화면에서 만들면 됩니다.

## 최근 업데이트 (게시글 수정/삭제, 모바일 반응형 등)

- **게시글 수정/삭제**: 모든 탭에서 이제 게시글을 수정·삭제할 수 있습니다.
  - 공지사항 / 레시피 / 자료실 / 업체 정보: **바이저만** 작성하므로, 수정·삭제 버튼도 **바이저에게만** 보입니다.
  - 건의함 / 본사 발주: **점주는 본인이 쓴 글의 "수정"만** 가능하고(삭제 불가), **바이저는 모든 글을 수정·삭제** 할 수 있습니다.
  - 글을 수정하면 목록에 "(수정됨)" 표시가 함께 뜹니다.
  - ⚠️ 이 기능이 동작하려면 `sql/02_edit_delete_migration.sql`을 SQL Editor에서 한 번 실행해야 합니다 (맨 위 안내 참고).
- **작성/수정 일시**: 모든 게시글에 날짜뿐 아니라 시간까지 함께 표시됩니다 (예: `09.17 14:32`).
- **모바일 반응형**: 좁은 화면에서 글자가 겹치거나 밀리지 않도록 레이아웃을 다듬었고, 상단 메뉴는 **햄버거 버튼**(☰)을 눌러 옆에서 펼쳐지는 방식으로 바뀝니다. 홈 화면의 "최근 공지사항 / 최근 건의사항"도 모바일에서는 위아래로 분리된 카드로 보입니다.
- **홈 화면 빠른 메뉴 카드 2개 추가**: `home.html`의 `quickMenuGrid` 안에 주석으로 표시해둔 자리에 임시(placeholder) 카드 2개를 넣어뒀습니다. 제목/설명과 `href="#"` 부분을 원하는 링크로 바꿔서 사용하세요.
- **필독 공지 자동 전환**: 필독 공지가 2건 이상이면 홈 화면 배너가 8초 간격으로 자동으로 다음 공지를 보여줍니다 (하단에 점으로 몇 번째인지 표시).
- **홈 화면 공지사항도 필독 우선 정렬**: 공지사항 탭과 동일하게, 필독 공지가 항상 최상단에 먼저 노출됩니다.
- **최근 건의사항 미리보기**: 홈 화면 "최근 건의사항"에 내용이 20자까지 미리보기로 표시되고, 그 이상은 "…"으로 줄여서 보여줍니다.
- **레시피 썸네일**: 유튜브 링크를 넣으면 실제 영상 썸네일이 카드에 자동 표시됩니다.
- **NEW 표시 자동 소멸**: 레시피의 "NEW" 표시는 등록 후 14일이 지나면 자동으로 사라집니다.

## 최근 업데이트 2 (GOMANGO 리브랜딩, 건의함 구분, 발주 카탈로그/가격)

발급받은 아이디/비밀번호로 로그인합니다. 계정이 없으면 바이저에게 문의해야 합니다. 로그인하지 않은 상태로 다른 페이지 주소를 직접 입력해서 들어와도, 화면 내용이 그려지기 전에 바로 로그인 화면으로 이동하도록 처리되어 있습니다 (비로그인 사용자에게 내용이 잠깐이라도 노출되지 않습니다).

**홈 (home.html)**
로그인 후 첫 화면입니다. 필독 공지가 있으면 상단 배너로 보여주고(2건 이상이면 7초마다 자동으로 다음 공지로 넘어가며, 배너 우측 하단 ‹ › 버튼으로 직접 넘길 수도 있습니다), 레시피/공지/건의함/본사 발주/자료실/업체 정보 6개 블록 + "포스터 및 배너 발주"/"물류 발주" 외부 링크 카드 2개를 보여줍니다. 각 카드를 클릭하면 해당 메뉴(또는 외부 사이트)로 이동하고, 아래쪽에는 최근 공지사항(필독 우선, 20자 미리보기)과 최근 건의사항(20자 미리보기 + 답변 미리보기)이 요약되어 표시됩니다.

**신메뉴 레시피 (recipes.html)**
왼쪽에서 카테고리(전체/신메뉴/시즌 메뉴/베이직 메뉴) 탭으로 필터링하고, 레시피 카드를 클릭하면 오른쪽에 상세 정보(제조 영상 링크, 재료, 제조 순서, PDF 다운로드)가 나타납니다.
- **점주**: 조회만 가능합니다.
- **바이저**: 우측 상단 "+ 새 레시피 등록" 버튼으로 새 메뉴를 추가할 수 있고, 상세 화면 하단의 "수정"/"삭제" 버튼으로 기존 레시피를 고칠 수 있습니다. 제조 영상은 파일을 직접 올리지 말고 유튜브(**꼭 "일부공개"로 설정**)나 구글 드라이브에 올린 뒤 링크만 입력하세요 (Supabase 비용 절약).
- 유튜브 링크를 입력하면 카드 썸네일이 실제 영상 썸네일로 자동 표시됩니다 (유튜브가 아닌 링크는 재생 아이콘만 표시).
- "NEW" 표시는 등록일 기준 **14일간 자동으로 붙었다가 저절로 사라집니다** (별도로 끄는 버튼은 없습니다). 기간을 바꾸고 싶으면 `assets/app.js`의 `isWithinDays(r.created_at, 14)` 부분과 `home.html`의 `14 * 24 * 60 * 60 * 1000` 부분의 숫자 14를 원하는 일수로 바꾸면 됩니다.
- **유튜브 공개 범위 주의**: "비공개"로 설정한 영상은 소유자가 구글 계정으로 개별 공유한 사람 외에는 썸네일도, 링크 클릭 후 재생도 되지 않습니다 (점주들이 각자 구글 계정을 등록해야 해서 사실상 이 게시판 구조와 맞지 않습니다). 링크를 아는 사람은 누구나 볼 수 있게 하려면 반드시 **"일부공개(Unlisted)"**로 설정하세요. 일부공개 영상은 검색에는 노출되지 않지만 링크로는 누구나 정상적으로 재생/썸네일 확인이 가능합니다.

**공지사항 (notices.html)**
전체 공지 목록을 최신순(+필독 우선)으로 보여줍니다.
- **점주**: 조회만 가능합니다.
- **바이저**: "+ 공지 작성" 버튼으로 제목/내용/분류를 입력하고, "필독 공지로 상단에 고정" 체크박스를 켜면 홈 화면 배너와 목록 최상단에 강조 표시됩니다. 각 공지 하단의 "수정"/"삭제" 버튼으로 기존 공지를 관리할 수 있습니다.
- **이미지 첨부(선택)**: 작성 폼의 "이미지 링크(구글 드라이브)"에 구글 드라이브 공유 링크를 입력하면 목록에 썸네일이 자동으로 표시되고, 클릭하면 새 탭에서 원본 이미지를 보거나 다운로드할 수 있습니다. 레시피 영상과 마찬가지로 파일을 직접 올리지 말고 구글 드라이브에 올린 뒤 링크만 입력하세요 (Supabase 비용 절약). 공유 설정을 **"링크가 있는 모든 사용자가 볼 수 있음"**으로 해둬야 썸네일이 정상 표시됩니다. 이 기능은 `sql/06_notices_image.sql`을 먼저 실행해야 동작합니다 (맨 위 안내 참고).

**건의함 (suggestions.html)**
상단에 건의함 게시판 이용 안내(접기/펼치기 가능)가 있고, 그 아래 건의사항 목록이 상태(답변대기/답변완료) 탭으로 필터링됩니다.
- **점주**: "+ 건의사항 작성" 버튼으로 **구분(건의사항/문의사항/메뉴 의견)**과 제목/내용을 남길 수 있습니다. **본인이 작성한 건의사항과 그 답변만** 볼 수 있고(다른 매장 글은 보이지 않습니다), 본인 글에 한해 "수정" 버튼으로 내용을 고칠 수 있습니다(삭제는 바이저만 가능).
- **바이저**: 모든 매장의 건의사항을 조회할 수 있고, "답변대기" 상태인 글에 답변을 입력해 등록하면 자동으로 "답변완료"로 바뀝니다. 모든 건의사항을 수정·삭제할 수 있습니다.

> 건의사항 공개 범위는 화면에서만 숨기는 게 아니라 Supabase DB의 보안 정책(RLS)으로 강제됩니다. 즉 점주 계정으로는 아무리 시도해도 다른 매장의 건의사항 데이터 자체를 서버에서 내려주지 않습니다.

**FAQ (faq.html)**
자주 묻는 질문과 답변을 목록으로 보여줍니다.
- **점주**: 조회만 가능합니다.
- **바이저**: 우측 상단 "+ FAQ 추가" 버튼으로 새 질문/답변을 등록하고, 각 항목 하단의 "수정"/"삭제" 버튼으로 관리할 수 있습니다.

**본사 발주 (orders.html)**
상단에 입금 계좌 안내가 고정으로 보이고, 건의함과 비슷한 구조입니다. 상단 상태 탭(전체/요청/발주완료)으로 필터링합니다.
- **점주**: "+ 발주 요청하기"로 **지정된 물품 목록에서 물품을 고르고**, 물품에 맞는 수량/단위(박스 수·사이즈·팩 수 등)를 선택해 요청합니다. 선택한 즉시 예상 금액이 표시됩니다. **본인 매장이 요청한 발주 내역만** 보이고, 본인 글에 한해 "수정" 버튼으로 내용을 고칠 수 있습니다(삭제는 바이저만 가능).
- **바이저**: 우측 상단 "발주 금액 설정" 버튼으로 품목별 단가를 설정할 수 있고, 모든 매장의 발주 요청을 조회할 수 있습니다. "요청" 상태인 건에 확인 내용(예: 입고 예정일)을 입력해 등록하면 자동으로 "발주완료"로 바뀝니다. 각 요청의 "송금 미완료/완료" 버튼으로 입금 확인 여부를 표시할 수 있고, 모든 발주 요청을 수정·삭제할 수 있습니다.

**자료실 (resources.html)**
매뉴얼, 서식, 포스터 등 문서 링크 목록입니다. 분류별로 색이 다른 태그가 붙어 한눈에 구분됩니다. 항목을 클릭하면 새 탭에서 링크가 열립니다.
- **점주**: 조회/다운로드만 가능합니다.
- **바이저**: "+ 자료 등록" 버튼으로 제목/분류/링크를 등록하고, "수정"/"삭제" 버튼으로 관리할 수 있습니다. 파일은 구글 드라이브 등에 올리고 공유 링크를 입력하는 방식을 권장합니다 (원한다면 Supabase Storage 버킷을 만들어 그 공개 URL을 넣어도 됩니다).

**업체 정보 (company.html)**
재료·장비 공급업체, AS 센터 등 연락처 목록입니다. 분류별로 색이 다른 태그가 붙고, 전화번호 옆 📞 아이콘을 누르면(모바일에서는) 바로 전화 연결이 됩니다.
- **점주**: 조회만 가능합니다. (전화 걸기는 가능)
- **바이저**: "+ 업체 등록" 버튼으로 새 업체 정보를 추가하고, "수정"/"삭제" 버튼으로 관리할 수 있습니다.

**계정관리 (accounts.html, 바이저 전용)**
상단 메뉴에 바이저 계정으로 로그인했을 때만 "계정관리" 항목이 보입니다. 점주 계정을 새로 만들거나, 매장명/권한을 수정하거나, 비밀번호를 재설정하거나, 계정을 삭제할 수 있습니다.
- **점주**: 이 메뉴 자체가 보이지 않고, 주소를 직접 입력해 들어와도 홈 화면으로 돌려보냅니다.
- **바이저**: "+ 계정 추가"로 아이디/권한/매장명/비밀번호를 입력해 새 계정을 만들 수 있고, 목록의 "수정"/"삭제" 버튼으로 기존 계정을 관리할 수 있습니다. 본인 계정은 삭제할 수 없습니다. 이 기능이 동작하려면 먼저 `admin-users` Edge Function을 배포하고(위 4-1단계 참고), `sql/05_service_role_grant.sql`을 SQL Editor에서 실행해야 합니다(맨 위 안내 참고).
- 계정 목록 우측 상단 검색창에 아이디나 매장명을 입력하면 실시간으로 목록이 필터링됩니다.
- 화면 맨 아래 **"오래된 게시글 정리"** 카드의 "3개월 지난 게시글 정리하기" 버튼을 누르면, 작성한 지 3개월이 지난 건의함·본사 발주 게시글(답변/댓글 포함)의 대상 건수를 먼저 보여주고, 확인을 누르면 JSON 백업 파일을 컴퓨터로 다운로드한 뒤 DB에서 삭제합니다 (DB 저장공간 확보용, Supabase Free 플랜은 500MB까지 무료입니다). 이 기능은 계정관리와 달리 별도 배포나 SQL 실행 없이 바로 동작합니다.
